本项目 Phase 2 纳入的风险

本项目 Phase 2 核心纳入两个风险。

第一个风险是供应商可用性下降。

该风险发生在外部供应商处，影响的是供应商每天能够释放给中心仓的订单数量。在正常情况下，供应商可以释放全部待处理订单；在产能不足或停产情况下，供应商只能释放部分订单，甚至完全不能释放订单。未被释放的部分不会直接消失，而是留在供应商积压订单中，等待后续继续处理。

该风险纳入 Phase 2 的原因是，它是最直接的供应端中断，会影响中心仓补货能否及时得到满足。如果供应商只能释放 80%、40% 或 0% 的订单，中心仓库存可能下降，进一步影响前置仓补货和顾客服务水平。

第二个风险是上游运输延误或停运。

该风险发生在供应商到中心仓的运输环节，影响的是供应商已经释放的货物什么时候能够到达中心仓。在正常情况下，供应商发出的货物按照基础提前期到达；如果运输延误，提前期会额外增加 1 天或 2 天；如果运输完全中断，已经释放的货物暂时不能发出，需要等待运输恢复。

该风险纳入 Phase 2 的原因是，它是最直接的上游运输中断，会影响中心仓补货到达时间。即使供应商已经释放货物，如果运输延误或停运，中心仓仍然可能无法及时收到货物，从而造成后续缺货。

本项目 Phase 2 暂不纳入的风险

中心仓作业能力下降暂不纳入 Phase 2。

中心仓作业能力下降包括收货能力下降、拣货能力下降或发运能力下降。如果加入这个风险，就需要为中心仓增加每日处理能力约束，例如每天最多能接收多少货、最多能向前置仓发出多少货。这会改变现有中心仓收发货逻辑，因此暂时留作后续扩展。

末端配送延误或中断暂不纳入 Phase 2。

现有模型假设中心仓向前置仓的补货是隔夜到达，也就是第 t 天晚上发货，第 t+1 天早上到达。如果加入末端配送延误，就需要为前置仓建立在途订单管道，并记录不同前置仓的配送延误情况。这会明显增加模型复杂度，因此暂时留作后续扩展。

需求激增暂不纳入 Phase 2 核心模型。

需求激增是需求侧冲击，例如某些前置仓或某些产品的需求突然增加。它确实会影响缺货、销售和利润，但它不是供应端或运输端中断。为了保持 Phase 2 的研究重点清晰，本阶段先不加入需求激增，而是把它作为后续压力测试。

产品特定供应中断暂不纳入 Phase 2。

产品特定供应中断表示某些 SKU 的供应受限，而不是所有产品都受同一供应商状态影响。加入该风险后，需要为不同产品设置不同的供应释放比例，模型参数和状态数量都会增加。Phase 2 第一版先假设供应商状态对所有产品按相同比例产生影响。

共同冲击暂不纳入 Phase 2。

共同冲击指天气、停电或信息系统故障等事件同时影响供应商、运输、中心仓作业和需求。例如极端天气可能同时造成运输延误和需求上升。该类风险需要考虑不同风险因子之间的相关性，不适合作为第一版中断模型直接加入。

Phase 2 的核心状态定义

根据 PDF 的建议，本项目将供应商可用性记为 A_t，并设置四个状态。

A0 表示供应商正常。此时供应商释放比例为 1.00，即可以释放全部待处理订单。

A1 表示供应商轻度产能不足。此时供应商释放比例为 0.80，即每天只能释放约 80% 的待处理订单。

A2 表示供应商严重产能不足。此时供应商释放比例为 0.40，即每天只能释放约 40% 的待处理订单。

A3 表示供应商完全停产。此时供应商释放比例为 0.00，即当天不能释放货物，订单继续积压。

本项目将供应商到中心仓的上游运输状态记为 U_t，并设置四个状态。

U0 表示运输正常。此时没有额外延误，货物按照基础提前期到达中心仓。

U1 表示轻度运输延误。此时新发运批次的提前期额外增加 1 天。

U2 表示严重运输延误。此时新发运批次的提前期额外增加 2 天。

U3 表示运输完全中断。此时货物不能发出，已经释放的货物进入运输等待队列，等待运输恢复。

联合中断状态

Phase 2 的联合中断状态定义为：

Z_t = (A_t, U_t)

其中 A_t 有 4 个状态，U_t 有 4 个状态，所以联合中断状态共有：

4 x 4 = 16 种

例如，Z_00 表示供应商正常且运输正常。Z_21 表示供应商严重产能不足，同时运输轻度延误。Z_33 表示供应商完全停产，同时上游运输完全中断。

供应商到中心仓的提前期公式

根据 PDF，基础提前期仍与 Phase 1 相同：

L0 ~ DiscreteUniform{1, 2, 3}

实际提前期由运输状态决定：

L = L0 + delta(U_t)

其中：

delta(U0) = 0
delta(U1) = 1
delta(U2) = 2

当 U_t = U3 时，运输完全中断，已释放货物不进入正常在途到货管道，而是进入运输等待队列，等待运输恢复后再发运。

转移矩阵

A_t 与 U_t 各自按马尔可夫链逐日转移。矩阵数值直接采用 PDF 给出的 M^A 与 M^U。

每天仿真结束时，按当前 A_t 从 M^A 对应行抽样得到 A_{t+1}，按当前 U_t 从 M^U 对应行抽样得到 U_{t+1}。若假设两条链相互独立，则联合转移矩阵为：

M^Z = M^A ⊗ M^U

得到 16 × 16 的联合状态转移矩阵。

矩阵验证

1. 行和检查

M^A 每一行概率之和均为 1：

A0 行：0.9950 + 0.0040 + 0.0008 + 0.0002 = 1.0000
A1 行：0.3000 + 0.6000 + 0.0800 + 0.0200 = 1.0000
A2 行：0.0800 + 0.2500 + 0.5500 + 0.1200 = 1.0000
A3 行：0.0200 + 0.0800 + 0.2500 + 0.6500 = 1.0000

M^U 每一行概率之和均为 1：

U0 行：0.9920 + 0.0060 + 0.0015 + 0.0005 = 1.0000
U1 行：0.4000 + 0.5000 + 0.0800 + 0.0200 = 1.0000
U2 行：0.1500 + 0.3000 + 0.4500 + 0.1000 = 1.0000
U3 行：0.0500 + 0.1500 + 0.3000 + 0.5000 = 1.0000

2. 平均停留时间

若状态对角转移概率为 p，则平均停留时间为 E[T] = 1 / (1 - p)。

对 M^A：

A0：p = 0.995，E[T] = 1 / 0.005 = 200 天
A1：p = 0.600，E[T] = 1 / 0.400 = 2.5 天
A2：p = 0.550，E[T] = 1 / 0.450 ≈ 2.22 天
A3：p = 0.650，E[T] = 1 / 0.350 ≈ 2.86 天

对 M^U：

U0：p = 0.992，E[T] = 1 / 0.008 = 125 天
U1：p = 0.500，E[T] = 1 / 0.500 = 2 天
U2：p = 0.450，E[T] = 1 / 0.550 ≈ 1.82 天
U3：p = 0.500，E[T] = 1 / 0.500 = 2 天

这说明正常状态 A0、U0 会长时间维持；一旦进入中断或延误状态，平均只持续约 2–3 天，然后有机会恢复。

3. 平稳分布

平稳分布 π 满足 π M = π，且各分量之和为 1。对 M^A、M^U 分别求解后，可得长期运行中各状态占比。直观上，因 A0、U0 的自留概率很高，平稳分布应主要集中在正常状态；中断状态出现频率较低，但一旦出现仍会对库存和服务水平造成短时冲击。

规则示例（用于后续接代码前自检）

假设中心仓今天向供应商订购某产品 100 件，并抽到基础提前期 L0 = 2。

若当天为 Z_00 = (A0, U0)：供应商释放 100 件，实际提前期 L = 2，两天后到中心仓。

若当天为 Z_21 = (A2, U1)：供应商只释放 40 件，剩余 60 件进入供应商积压；这 40 件的实际提前期 L = 2 + 1 = 3，三天后到中心仓。

若当天为 Z_33 = (A3, U3)：供应商释放 0 件，100 件全部进入供应商积压；运输也处于中断，当天没有货物进入正常在途到货管道。


Phase 2 核心货物流转

Phase 1 是：下单 -> 在途 -> 到货。

Phase 2 把上游拆成更细的一条链：

supplier_backlog
-> transport_waiting
-> supplier_pipeline
-> central_inventory

四个位置的含义：

supplier_backlog：供应商尚未释放的欠货（A_t 控制释放比例）
transport_waiting：货已准备好，但尚未进入运输（U_t 控制能否发出及延误）
supplier_pipeline：货已发出、正在路上
central_inventory：货已到达中心仓

每天晚上中心仓订货流程：

1. 计算库存位置
   库存位置 = 中心仓现货 + pipeline 在途 + supplier_backlog + transport_waiting
2. 若库存位置低于 s，按 (s,S) 计算订货量 Q，并加入 supplier_backlog
3. 按 A_t 释放：释放量 = floor(backlog * alpha(A))，剩余继续留在 backlog
4. 当日释放量先进入 transport_waiting
5. 按 U_t 决定发运：
   U0/U1/U2：从 waiting 转入 supplier_pipeline，
             实际 lead time = L0 + delta(U)，L0 ~ {1,2,3}
   U3：不能发运，货继续留在 transport_waiting
6. 每天早上 pipeline 中剩余 lead time 减 1；减到 0 时加入中心仓库存
